# CLAUDE.md

## Project

Public website for Uppsala Blåsarsymfoniker (wind orchestra): a static site
generated by Gleam from Markdown content, edited by the board through Sveltia
CMS at `/admin` and by agents directly in `content/`. Preview:
https://ubs-website.uppsalablasarsymfoniker.workers.dev/ (Cloudflare),
deployed from `main`. Cloudflare account: "Uppsala Blåsarsymfoniker"; the
`cloudflare` plugin reaches it.

| What | Where |
|---|---|
| What the site is and should be | `docs/plan.md`, edited in place |
| Why it is that way | `docs/decisions/NNNN-*.md`, one record per decision |
| What's done, next, and blocked | GitHub issues, grouped by milestone |
| Colours, type, logo, spacing | `docs/ubs-profile.html` (source of truth) |

## Status and work

Status lives in GitHub, not in files. To pick up work:

```sh
gh issue list --milestone "2 · CMS"     # the current milestone
gh issue list --label board             # waiting on the UBS board
gh issue view <n>
```

- **Milestones:** `2 · CMS`, `3 · Migration`, `4 · Launch`, `5 · Later`.
  Milestone 1 (core pages) is done.
- **Labels:** `board` (waiting on the board), `content`, `design`, `cms`,
  `decision` (needs a decision record), plus GitHub's defaults (`bug`,
  `enhancement`, `accessibility`, `documentation`).
- **New work** becomes an issue: a sentence of what and why, and
  **Done when:** (the template in `.github/ISSUE_TEMPLATE/task.md`). Add a
  milestone and labels.
- **Finishing** an issue: put `Fixes #n` in the body of the commit that
  completes it. Comment on the issue for progress worth keeping that isn't in
  a commit.
- **The repository is public**, so issues are too. Never put personal details
  in them: no board members' phone numbers or addresses, no member data.
- **Decisions:** use the `decision-record` skill whenever a choice is made,
  proposed, or changed. Records are never rewritten; a changed mind is a new
  record that supersedes the old one.

## Run it

```sh
gleam test                            # includes loading the real content/
gleam run build                       # writes dist/, runs Tailwind
python3 -m http.server 8000 -d dist   # preview at http://localhost:8000
```

`SITE_URL` sets the public address and base path; unset, the build targets
`http://localhost:8000`. To check that links survive a base path, build with
`SITE_URL=http://localhost:8000/ubs-website` and serve `dist/` under that path.

## Gleam CLI

Always manage the project and its dependencies with the `gleam` CLI. Never
edit `gleam.toml` or `manifest.toml` by hand to do something a command does.

| Task | Command |
|---|---|
| Add a dependency | `gleam add <package>` (`--dev` for test-only) |
| Remove a dependency | `gleam remove <package>` |
| Update dependencies | `gleam update` |
| Fetch dependencies | `gleam deps download` |
| Build | `gleam build` |
| Test | `gleam test` |
| Format | `gleam format` |
| Generate the site into `dist/` | `gleam run build` |

## Git

- Use [Conventional Commits](https://www.conventionalcommits.org/)
  (`feat:`, `fix:`, `chore:`, `docs:`, `refactor:`, `test:`, `ci:`, and
  `content:` for changes in `content/`, which is also what the CMS writes).
- Work directly on `main`. Don't create feature branches or pull requests
  unless asked.
- Make small commits as you go: one logical change each, committed as soon
  as it builds and its tests pass, rather than one large commit at the end.

## Code style

- **Swedish first, English throughout.** User-facing text exists in both
  languages; code, comments, and commit messages are English.
- **Result types for errors.** Content problems are returned as an
  `error.Error` naming the file, so an editor can fix them from the CI log.
  No `let assert` or `panic` outside `test/`.
- **Layout:** follows Hayleigh Thompson's `hayleigh.dev` (`data/`, `view/`,
  `meta/`, one build module); chosen deliberately, so don't flag it as
  grouping by design pattern.
- **Internal links** go through `route.href` / `route.asset`. A literal
  `"/konserter/"` breaks whenever the site lives under a path.
- **UI strings** go through `language.pick(swedish:, english:)`; the labelled
  arguments make a missing translation a compile error.
- **`lang="sv"`** goes only on Swedish content text (title, summary, body) on
  an English page, never on the wrapping article.
- **Match all variants** of our own types; no `_ ->` catch-alls.
- **Brand and spacing:** the `ubs-brand` and `tailwind` skills hold the rules.
  Theme tokens only, never hex; the 4px spacing scale, no arbitrary pixels.

## Tooling

- `.claude/agents/gleam-reviewer.md`: run it before committing Gleam work.
  If the session didn't start in this folder, the agent type isn't
  registered: run a general-purpose agent and tell it to follow that file.
- `.claude/hooks/gleam-format.sh` formats `.gleam` files after each edit.
- `.mcp.json` provides the `gleam_packages` server for Hex package docs.
- Skills in `.claude/skills/`: `ubs-brand`, `tailwind`, `decision-record`.

## Known quirks

- **Two Workers:** `wrangler.jsonc` at the root is the site;
  `workers/cms-auth/` is the CMS sign-in service, deployed by its own
  workflow. Both deploy with the `CLOUDFLARE_API_TOKEN` repository secret.
- **Tailwind** is downloaded by `glailglind` on first build into
  `build/bin/`; the version is pinned under `[tools.tailwind]` in
  `gleam.toml`.
- **Nested captures** like `list.any(xs, string.ends_with(file, f(_)))` are
  invalid Gleam, and `gleam format` won't fix them. Use an explicit `fn`.
- **Collections reject unknown files:** anything in `content/concerts/` or
  `content/news/` not named `<slug>.sv.md` / `<slug>.en.md` fails the build.
  Hidden files (`.DS_Store`) are ignored.
- **Tailwind's `max-w-prose` is 65ch**, not the site's 68ch reading width;
  use `max-w-(--container-prose)`.
